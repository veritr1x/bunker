# Clean normal-entry Unity numeric min/max refresh

This is a separate, unselected component after the IL2CPP text-mesh repair.
The sealed plan `work/unity-nm-clean-plan1/plan.json` identifies 131 clean FDE
starts in 62 Unity object modules. Seven interior heads and eleven bodies with
mixed instruction errors remain excluded. The plan's original authorization
fields describe its earlier inventory stage; subsequent preparation was
authorized separately. It does not authorize selection or a game run.

`build_unity_numeric_minmax_retained_overlay.py` requires explicit object
indices and fresh output directories. It uses the frozen qualified lifter
`73a1d6cf…` and semantics `24e908b3…`. Each target is lifted and polled separately;
accepted targets are spliced into their original module before one native
compilation. Newly exposed unsupported guest instructions cause that body to
remain unchanged and be recorded as held. Counts describe actual accepted
bodies, rather than treating the entire proposed population as repaired.

Every splice records reversible operations for the function, appended records,
and named call metadata. Reversing all operations must recover each complete
original raw and polled module. All original numeric metadata definitions and
all 128 minus N neighboring function bodies must remain exact. Final optimized
IR must pass the existing cooperative-poll and guest-call-transfer audit; all
native guest references must resolve within the existing trace inventory.
The State closure remains 1200 bytes with alignment 16.

Fresh code can require a local vector-wrapper declaration absent from the old
truncated module. Only named integer/float wrappers containing primitive arrays
of 64 or 128 total bits may append. Existing names and declarations are preserved,
and the State closure must remain unchanged. The appended declarations are part
of the exact inverse. Module232 independently verifies its new `uint64v2_t` against
the frozen semantics and LLVM18 layouts for both AArch64 and Windows: size16,
ABI alignment8, with fresh allocations aligned16. Future distinct wrappers need
their own recorded checks before admission.

Native preservation initially uses
`coff_readonly_constant_preservation_pcmpeqd.py`, a separate copy of the frozen
original checker. It adds only the legacy SSE2 PCMPEQD constant-read profile.
The separately qualified `coff_readonly_constant_preservation_pcmpeq.py` adds
PCMPEQB for the reached module360; both forms require 16-byte memory reads,
excluding MMX. Every protected constant reference is
checked, including unchanged displacement fields. Constant sections must be
readonly, relocation-free, adequately aligned, and provide identical complete
read payloads. The original checker used by the existing game build is unchanged.

The extension is qualified against the eight saved IL2CPP objects and both
two-target Unity pilots, protecting 1268 functions. Seven negative controls cover
payload changes, alignment, another compare opcode, memory writes, address taking,
MMX width, and embedded relocations. Its primary instruction contract is in the
[Intel instruction reference](https://cdrdv2-public.intel.com/835757/325383-sdm-vol-2abcd.pdf).
The source preparation records the exact two-edit inverse and unchanged ASTs
for all other checker functions.

The additional PCMPEQB profile is qualified on the saved three-target module360
(125 protected functions) and the existing PCMPEQD pilot, with seven focused
negative controls. It changes no guest instruction semantics and requires no
relift or recompilation of module360. The first integrated snapshot contains
52 actually qualified modules and 92 accepted heads, merged onto the exact
current owner overlay. It preserves all 4661 object positions, including the
IL2CPP8 replacements and appended TMP object, all four headers, the 595556-head
inventory, current host sources and bootstrap. Later modules remain separate.

The remaining preparation explicitly holds two discovered cases. Head
`70d3f964` has a real direct branch to a two-instruction island just beyond its
FDE byte range, producing a missing-block terminal rather than an unsupported
opcode. Head `70db2d88` exposes unsupported `FCVTN V5.4H,V5.4S` after its numeric
min/max prefix. Their original bodies remain unchanged. No extra source range,
trace head or instruction family is admitted for those cases.

Completed object artifacts, failed attempts, saved target IR, and qualifications
remain separate immutable outputs under `work/unity-nm-*`. This component changes
no host source, header, original ELF or instruction semantics. Its old-parent
object indices are disjoint from the IL2CPP8 replacements and appended TMP entry
object; a future selected overlay must merge those current changes explicitly.
Static preparation does not establish complete function execution, a visible
frame, or working gameplay.
