# CNT.8B and UADDLV.H/8B

The original Unity run reported unliftable PC `0x7033b784` after `CNT V0.8B,V0.8B` (`0x0e205800`) at `0x7033b780`. The next instruction is `UADDLV H0,V0.8B` (`0x2e303800`). Both forms lacked lowering. The enclosing function is the 308-byte FDE `0x7033b734..0x7033b868`; its first loop counts bits in seven 64-bit loads.

[integer_popcount8b_source.py](integer_popcount8b_source.py) adds only Q=0, size=0 decoders and two selectors. CNT snapshots eight source bytes, writes each byte's population count, and clears the destination's upper 64 bits. UADDLV snapshots eight unsigned bytes and writes their sum, at most 2,040, to the low 16 bits while clearing the other 112 bits. Both support generic Rd/Rn and source/destination aliasing; neither changes NZCV, FPCR or FPSR. Other arrangements remain outside this addition.

[build_integer_popcount8b_toolchain.py](build_integer_popcount8b_toolchain.py) reproduces the isolated build with `--execute`, using the pinned NEG.4S baseline and inherited compile recipe. It rebuilds Arch.cpp, Decode.cpp and instruction semantics with at most two workers, borrowing unchanged lifting, lowering, extraction and other archive members. [The build receipt](../work/integer-popcount8b-preparation1/build1/acceptance.json), SHA-256 `d24e0a81215b8c636da04505b220f37ab5b8491ef78cecc6b071ee22aabbabcf`, freezes lifter `f967bf3b57f889d7ea549fb3319a0facb7729f3e6ebbc83fea0b7c74bdadd5a3` and semantics `469903ec4d84cbd38e7631cdc1836c925dbf5a8d1b63183b34867671660a3585`. Its actual compiled identity comparison preserves all 1,270 previous semantic functions and 1,431 selectors, including NEG and prior FP operations. Attribute IDs are resolved by content; only inline-assembly source coordinates are excluded. Preservation does not remove previously documented FP edge limitations.

[test_vector_cnt_8b.py](test_vector_cnt_8b.py) compares the same NDK kernel object on actual static Bionic/AArch64 under QEMU, raw Windows translation and exact poll-instrumented Windows translation. Six kernels cover alias and distinct-register CNT, the exact adjacent CNT/UADDLV pair, alias and distinct-register standalone UADDLV, and the original seven-load/56-byte loop prefix with a bounded wrapper. Inputs cover all 256 byte values in every lane plus 16 edge vectors, including UADDLV's 2,040 maximum and the loop's 448-bit maximum. Two source/output memory alias arrangements and four architecture-status seeds produce 13,056 records per platform.

[Final reference 4](../work/vector-cnt8b-reference4/acceptance.json), SHA-256 `9f12b847a196abf3db4da3e8df9cd1f72c81f7289d9503ec19c8b5e1bbbcc569`, and [qualification Q1](../work/vector-cnt8b-qualification1/acceptance.json), SHA-256 `48cf6c0bf676d74c07fcb757f01ed43587334f8e3553ec86529fc7fc43f4ee82`, passed with exact records and no output normalization. Windows checks the full 1,200-byte State, Memory64 identity/content and complete guarded buffers against an independent bit model. Destination clearing and status preservation are checked; the loop additionally checks its counter registers, final vector and genuine CMP-produced NZCV.

This is instruction-kernel and actual-prefix qualification. It does not execute the enclosing 308-byte function or any of the nine selected target functions, supply helper results, establish live argument values, or claim an original game frame. Whole-function lowering, container preservation and subsequent original-game integration are separate evidence.
