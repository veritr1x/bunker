Its wrapper loaded context slot `+0x4f8`, populated by the failed `glDrawBuffers` lookup, and tail-called it. The actual count was 1 and the array pointer was 64-bit; array contents were not logged. The single production change is `gl_host.cpp`, SHA-256 `2a52cd1b41c7eb8226750bf3233640b6de5dcc590eb78f0835d92c1f5ab4cbb7`. It appends command index 142, preserving the previous 142 names and markers exactly, for 143 commands total. The typed signature is `void(GLsizei, addr_t)`: signed 32-bit count and full 64-bit pointer. Valid positive counts use a tracked `n * sizeof(GLenum)` snapshot copied into aligned owned storage, then call the real ANGLE `PFNGLDRAWBUFFERSPROC`. Nonpositive counts and null pointers delegate directly; counts above the actual current-context maximum delegate without reading the guest array. The existing context selection and native-environment guards remain in force.

The internal maximum query preserves existing GL errors through GlHost's per-context pending-error set. The guest-visible `glGetError` retrieves those flags exactly once even when the internal query has drained the raw driver queue.
