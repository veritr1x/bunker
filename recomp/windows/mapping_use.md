# Active use of owned Windows mappings

`FileSystem::MappingUse` contains the actual owning `MappingInfo region` and a strong `std::shared_ptr<void> lease`. `AcquireMappingUse(address,length,writable)` first verifies the complete nonempty span against the same owned-mapping registry and actual committed native page protections used by `MappingRegion`. It returns the full owner base, rounded byte size and process-monotonic lifetime generation, then pins that whole owner. Unknown/external memory, overflow, spans crossing owner bounds, inaccessible or guarded pages and insufficient write permission are rejected without changing virtual errno.

The existing recursive mapping mutex covers lookup, actual permission validation, generation validation and token acquisition. Every owner has a shared atomic active-use control. Each successful acquire creates one token that increments the real count under that mutex; copies of a MappingUse or its lease share the token until its final strong reference is released. Independent acquires create independent counted tokens. Final release only decrements the shared atomic control: it has no Impl pointer, provider callback, mutex, native free, protection change or tracked-memory write.

Valid full-owner `Munmap` rejects an active owner before invalidating epochs, unmapping/freeing native memory or closing its file mapping object. `Mprotect` validates its existing input shape, then checks every intersecting pinned owner before any VirtualProtect call, even for a range that subsequently fails the existing single-owner profile. The rejection throws an explicit unsupported-profile diagnostic; it supplies no invented errno, successful no-op or deferred-unmap success. Ordinary operations proceed using their existing native behavior after the last lease is released. MAP_FIXED remains unsupported; real MAP_FIXED_NOREPLACE still cannot replace live allocations. MADV_NORMAL does not discard the mapping.

`MappingRegion` remains a snapshot with no lease. Installed alternate-stack/nonlocal metadata must retain only this snapshot, so an unused or failed-restoration stack can still be unmapped by the actual original cleanup. An actual active frame asks for a MappingUse and must compare its returned full region and generation with its saved registration before retaining the lease. An allocation identity does not prove the C lifetime of a Unity arena subobject inside that mapping. Consumers retain their genuine frame/object lifetime checks too.

FileSystem must outlive its API calls and every active use. Its Impl destructor first scans all pin controls before any mapping or errno retirement. A live use prints the owner identity and aborts explicitly; it never unmaps underneath the active frame. Concurrent destruction with an API call is outside the C++ owner lifetime contract. All mutation of these allocations during active use must go through the guarded provider ownership path.

## Validation

The Windows-focused NDK fixture calls real mmap, mprotect, munmap and mapped byte loads/stores through the installed provider. Tests use actual anonymous allocations and real file views with a4KiB guest offset, including fd-close survival, interior spans and native read-only/guarded page validation. They verify whole-owner exclusion, copied and independent token lifetime, unchanged bytes/native permissions/generation/errno/guest exclusive reservations on rejected mutation, actual NOREPLACE rejection and ordinary native cleanup after release.128 acquire-vs-unmap/protect races retain a winning lease until both racers finish and assert exactly the safe ordering. Observed race counts are reported rather than assumed. Subprocesses require explicit fatal diagnostics for actual NDK mutation while pinned and destruction with a live pin.

The runner freezes committed11d2dca support and overlays only the owned filesystem provider and new focused fixture/test. It runs existing FS116 using fresh APK/sandbox data, retaining and hashing the original immutable translated fixture/object files. It does not change old artifacts or include live SignalHost edits. Linux SignalHost tests use their separately owned real native mmap backend. These tests establish the mapping-use provider; no actual signal delivery or game frame is claimed here.
