# Instance JNI long-return handlers

DefineLongMethod takes an int64_t callback and an exact J-result descriptor. CallLongMethod/V/A use JNI slots52/53/54, the existing virtual receiver lookup, bounded three-argument grammar and owned local callback frame. The result preserves all64 bits in X0, including negative values. Java exceptions return exceptional zero while retaining the pending Throwable. Existing int/float/object paths are unchanged. Static/nonvirtual long slots remain explicitly unsupported; no Bind or framework method is added by this component.

The focused gate compiles actual Android NDK zero/mixed-reference/J/I callers once and uses the same object in an ARM64 native ABI reference and both lifted host executables. The reference supplies native JNI table callbacks, not a JVM/Android framework emulation. It verifies signed/extreme and beyond32-bit results, immutable va_list/jvalue arguments, following result-memory effects, SP/callee registers, virtual base/interface selection, owned temporary and borrowed-local lifetime, reentrant cleanup, Java/C++ exceptions and validation errors. One unchanged existing jni_numeric test runs once per host. No game, display, scheduling or rendered-frame claim.
