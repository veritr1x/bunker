# Guest comparator binary search

Game15 naturally passed the repaired prefetch instructions, then reached original `bsearch` at LR `0x82577480`. Original caller FDE `0x2577448..0x257749c` supplies 16-byte rows and comparator `0x82580bd0`. The original comparator loads the key/row first words, subtracts in W0 and returns. These values identify the observed call; production contains no special case for them. This is a component port, not proof that IL2CPP initialization or rendering completed.

The primary [Android 13 Bionic implementation](https://android.googlesource.com/platform/bionic/+/android-13.0.0_r1/libc/upstream-netbsd/lib/libc/stdlib/bsearch.c) uses a `size_t` remaining count and a midpoint probe. Independent audit `work/game15-bsearch-peer1` pins source SHA256 `0205e72ac3c3555e26c86c59324c29cec66ccbcb058739e6cd46840ec1000cdc`, Android.bp selection and the forced NetBSD compatibility header. Its diagnostic assertion macro expands to nothing. Thus an empty search returns null without evaluating key, array or comparator; a zero-width nonempty search still calls the comparator on the same array address as the count halves. The provider preserves that behavior and Bionic's duplicate-element selection/order.

`LibC::BinarySearch(key, base, count, size, comparator)` uses LP64 counts and a guest callback address. The typed five-argument bridge receives X0â€“X4 and returns an original element pointer in X0. The `bsearch` marker is appended after `setlocale`, preserving all prior marker identities. Each comparator receives the exact original guest key and element addresses; no host function pointer is formed. Only signed low W0 controls ordering; high X0 bits are ignored.

The existing `LibC::Runner` supplies synchronous callbacks. Production already connects it to `Pthreads::Run`, which validates the registered translated-entry role, copies the current active State with its owned SP/TLS, scopes nested execution, and verifies the normal PC/SP return. No new callback engine, private manual initializer or hard-coded result is introduced. There is no LibC or memory-tracking lock around comparison, so reentrant searches and real comparator memory/errno side effects remain observable. Provider itself performs no key/array reads, memory snapshots, guest writes, epoch invalidation or errno change. Nested Runtime/import entry may clear an exclusive reservation; no reservation-retention guarantee is claimed.

For nonempty searches, multiplication of count by width and the full base-plus-span endpoint must fit the 64-bit guest address space before any comparator is dispatched. An unrepresentable span is an explicit unsupported/invalid-profile exception, not a fake not-found result or errno return. Nonempty searches require a nonzero comparator and an installed Runner. Missing/unregistered targets fail decisively through the established callback-role check. Direct C++ calls may throw; the production `LibC::Add` bridge catches failures and aborts with the import name before any exception can unwind through lifted LLVM. The provider does not pretend it can validate the comparator's arbitrary memory accesses or unknown key width.

Only the two LibC files and this new document change provider behavior. Existing providers, mutable status APIs, game flow, Remill semantics, engine objects and cleanup ownership are untouched. Keep the LibC/Runner/runtime/module alive and workers quiescent under the existing lifecycle contract while searches execute. The input array must satisfy the normal binary-search comparator/sorted-array contract; this adapter does not make an unsorted or concurrently mutated array well-defined.
