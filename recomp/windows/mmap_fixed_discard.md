# Owned anonymous fixed discard

The supported Windows-port profile is exactly `MAP_PRIVATE | MAP_FIXED | MAP_ANONYMOUS` (`0x32`), `PROT_NONE`, descriptor `-1`, offset zero. The nonzero page-aligned range must fit completely inside one existing, ordinary anonymous FileSystem allocation. File views, growdown reservations, foreign/native allocations, unowned addresses and ranges crossing owners are rejected. Registry ownership is mandatory; VirtualQuery alone never confers ownership. Native target pages must still be committed private pages of that exact reservation and may not be guarded.

The original IL2CPP GC helper at `825a8b38..825a8bd0` rounds its input interval inward and requires this call to return its exact requested address. Its connected restore helper `825a8e08..825a8ecc` later calls mprotect on the same interval with RW or RWX. Static proof is in `work/runtime12-mmap-boundary1/acceptance.json`. The actual Runtime12 target address was not logged, so its ownership has not been inferred from GC intent.

All intersecting whole-owner MappingUse pins are checked before a native mutation, including uses of a disjoint subrange. After validation a fresh generation is preallocated. The existing nonrecursive guest-memory mutex covers the complete native prepare/invalidate/commit sequence through `WithGuestMemoryMutation`. Prepare decommits only the target pages and, on success, refreshes the owner generation. Target exclusive epochs are then invalidated, and the same reserved pages are committed PAGE_NOACCESS. The reservation is never released and no address fallback occurs. Later ordinary mprotect exposes newly zero-backed pages. Unchanged pages keep their bytes and native protections.

Partial replacement conservatively refreshes the generation for the ENTIRE native owner. Every earlier MappingInfo snapshot is stale, including snapshots of unchanged subranges. This is deliberate fail-closed lifetime revocation; it is not Linux VMA segmentation or subobject-lifetime tracking. New accessible-subrange queries see the new generation. Whole-owner pins and existing full-owner munmap cleanup remain unchanged.

A false native prepare must mean no bytes, protections or ownership changed. A failed decommit therefore changes no target epoch or owner generation. After decommit, old contents are irretrievable: invalidation or recommit failure raises a named destructive failure, with the reservation retained. No untouched-failure, rollback or successful remap is claimed. Native callbacks only issue short virtual-memory operations and update captured scalar state; virtual errno, diagnostic formatting and exceptions are handled outside the memory lock. Existing runtime function bodies remain byte-exact.

[VirtualFree](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualfree) documents that decommit retains reservations and destroys contents. [VirtualAlloc](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualalloc) guarantees zero backing for newly committed pages; MEM_RESET does not guarantee zeros and is not used.
