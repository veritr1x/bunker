# Raw64 and reference-array JNI callback arguments

The original APK declares `bitter/jnibridge/JNIBridge.newInterfaceProxy(J[Ljava/lang/Class;)Ljava/lang/Object;`. The game5 frame reaches its real `CallStaticObjectMethodV` entry after the Settings and object-array providers. This change supplies the argument ABI and metadata needed by a separately owned Java adapter; it supplies no proxy factory body or service callback result.

`Host::MethodArguments` remains three machine slots. `J` preserves all 64 bits without handle lookup or reference cloning. `I` retains its existing low32 contract. Object and reference-array descriptors are validated against the actual referenced class, with the complete array descriptor retained for covariance checks; `Object[]` containing class objects cannot stand in for `Class[]`. Null and cleared weak reference arguments become null callee slots. Primitive arrays, floating-point argument types and more than three argument slots remain unsupported.

`BindStaticObjectMethod` and `BindStaticVoidMethod` attach a supplied body only to an exact existing static, nonnative, unimplemented declaration. Missing declarations, duplicate implementations, native methods and instance declarations are rejected. Existing defining APIs still reject duplicate declarations. Static void JNI entries141/142/143 use the existing direct/V/A argument decoder by normalizing to114/115/116 and then the ordinary static owned callback frame with a void return-kind check.

Each supplied handler receives a fresh borrowed local class receiver and fresh borrowed locals for reference arguments. Its temporary locals and unbalanced nested local frames are retired before returning, on success and Java exception paths. Raw64 arguments remain scalars even if their bits equal a live reference handle. Result promotion, exception propagation and retirement outside the provider lock use the existing callback mechanism.

The optional final `interfaces` argument to `DefineClass` declares genuine implemented interfaces. Every entry must name a previously declared interface and duplicates are rejected before publication. Assignability visits the declared interfaces at each superclass node, including array covariance. This metadata does not execute Java constructors or provide interface callback implementations. Existing classes keep their previous behavior when the new argument is omitted.

`ClassNameValue(jclass)` reads the exact internal metadata name, including complete array descriptors, without executing Java or invoking `getName`. Null or cleared weak references return no value; invalid handles preserve the ordinary reference diagnostic, and live non-Class objects raise `IllegalArgumentException`.

## Validation

`jni_long_array_guest.c` is compiled by the original Android NDK API24 toolchain and translated under the accepted immutable Remill semantics. It calls actual JNI direct, V and A entries, including register-to-stack split and wholly stack-backed AAPCS64 varargs. Host tests cover all64-bit patterns, typed and nested arrays, explicit interface implementations/inheritance, static binding guards, static void calls, class metadata, return-kind/type failures, Java exceptions, canaries, borrowed-reference lifetime during original-global deletion, reentrant payload retirement and attached concurrent workers.

`test_jni_long_array.py` freezes a committed support source tree and overlays only the two owned JNI provider files plus the new fixture/test. Each candidate uses a fresh output directory. It builds and runs focused and existing JNI, Java initialization, Android Context, package manager, callback frame, constructor frame and object-array gates on Windows x86_64 and Linux x86_64. The union fixture, generated headers, copied source, compiler manifests, binaries and logs are hashed in its acceptance report. The enabled-AR gate must retain its explicit unsupported-side-effects failure.

Candidate1 is preserved: the new test incorrectly supplied a null Env from unattached worker threads. Its guest null load was located with GDB; the test now explicitly attaches/detaches workers through the JavaVM. No provider change was needed for that failure. Candidate2 passed on Windows and Linux:861 focused checks and81 actual raw64/array callback calls per host; existing gates JNI36, Java141, Context14, package manager155, callback464, constructor362 and object-array1450 all passed on each host. Both union lifts contain43 traces with zero unsupported traces or unresolved direct targets. The enabled-AR failure remained explicit.
