# Exact Android 13 sscanf `%llu` profile

The normal Unity startup path reached `sscanf` at original caller RVA `9bedc0` with the exact NUL-terminated format `%llu` at `ecd1e2`. The caller passes one eight-byte output at X2/SP+8 and consumes it only when W0 equals1. Independent original-APK provenance finds `buildDate=638477124699603280` in `assets/bin/Data/boot.config`; this is an input observation, not a replayed result.

`LibC::ScanUnsignedLongLong` supports this exact format, appended after getpid in the import marker table. All older markers, including free, retain their identities. It uses the existing `LibC::Add` exception fence; an unsupported format prints a named import failure and aborts before it can unwind through lifted nounwind code. Direct host calls throw the same named error.

The implementation snapshots format and input through the shared guest-memory protocol before any output effect. It skips the six Bionic ASCII whitespace bytes, accepts one optional sign and decimal digits, and limits the token to512 characters including the sign. Empty/whitespace-only input returns signed32 `-1`; nonempty no-digit/sign-only input returns0. Both leave output and guest errno untouched and do not dereference a failure-only output. A valid conversion returns1 and publishes exactly eight bytes through `WriteGuestMemory`, including a same-value assignment. Successful nonoverflow preserves guest errno. Unsigned negatives wrap modulo2^64; magnitude overflow, including negative overflow, stores UINT64_MAX and sets Android ERANGE34, with returncount1. For512 zeros followed by1, assignmentcount is1 and value is0.

These choices follow pinned Android13 Bionic [vfscanf.cpp](https://android.googlesource.com/platform/bionic/+/android-13.0.0_r1/libc/stdio/vfscanf.cpp), [strtol.cpp](https://android.googlesource.com/platform/bionic/+/android-13.0.0_r1/libc/bionic/strtol.cpp), [vsscanf.c](https://android.googlesource.com/platform/bionic/+/android-13.0.0_r1/libc/upstream-openbsd/lib/libc/stdio/vsscanf.c), and [ASCII ctype definitions](https://android.googlesource.com/platform/bionic/+/android-13.0.0_r1/libc/include/bits/ctype_inlines.h). The scanner uses strtoumax; both strtoumax and strtoull instantiate the same unsigned template at64-bit width. This is not a general scanf implementation: other formats, widths, extra conversions and formatting tails are explicit unsupported boundaries.

Read-only primary-source evidence is preserved in `recomp/work/sscanf-llu-bionic-audit/REPORT.md` (SHA651c217582df455e742facc1633ec0e746d9391aeedbb63cd164e8c50823f35b) and evidence.json (SHA94ac544de9adafcb956945b997d0c49c3ed9a683742f67e2b4addb0af9473d61). Its26-case plus overlap executable extracts the original scanner block and unsigned template with small documented string-FILE adapters. That reference is source-derived, not a complete Bionic runtime execution or an ARM64 ABI proof.
