# Passive Windows thread-container lifetime repair

This change closes the three remaining concrete nontrivial emulated-TLS storage defects identified in the exact Game12 executable after the locale repair. Independent original ownership/order proof is preserved at work/production-tls-inventory1/REPORT.md (SHA54ea814a8e3853a3c59967a865b9d0875cce1b1b1673d903ab4c92c0e4759165). On this GCC15.2/MinGW-w64 13.0.0 build, std::thread's winpthreads wrapper cleans pthread keys (including emutls allocations) before later native C++ TLS callbacks. A map/vector destructor holding the freed emutls object pointer is unsafe. Raw _beginthreadex native exit has a different callback order; changing first-touch order or observing a lucky successful exit cannot fix this ownership defect.

The repaired owners are Pthreads::Impl::Bindings() (map of provider IDs to **borrowed raw Thread pointers**), EglHost's per-owner error map (integer values), and GameAutomaticEnvironments::Frames() (scalar Frame vector). Each Windows owner has one checked process-lifetime native pthread TSS key and a separately allocated heap container per native thread. C++ static key initialization can report a native key error outside any C callback. A unique_ptr owns an unpublished container until setspecific succeeds; failed publication deletes that container and fails decisively. No allocation failure is converted into an empty/default success profile.

The real native key destructor deletes only its container and nodes/backing array. It never deletes Thread, closes handles, releases Thread/payload leases, calls guest TLS destructors, invokes hooks/NonlocalJumps/Forget, or accesses a provider. Explicit ReleaseCurrent/worker Finish/Join/Shutdown, native current-context release, error clear-on-read, frame normal-pop and Forget are unchanged owners. Provider IDs, stable Thread tokens and registry tombstones retain their existing semantics. All keys/callback code outlive workers; provider/guest cleanup remains explicit and externally quiescent.

Helpers are local to the three owners; no new shared header/build dependency is introduced. The game detail header is included inside an anonymous namespace, so pthread.h is included globally in game_bootstrap.cpp and the focused driver. Existing Linux map/vector TLS branches are unchanged where present; these Windows providers are not being advertised as new Linux implementations. Process-lifetime keys/main-thread empty bookkeeping containers are intentionally retained; worker heap containers are really destroyed by native TSS cleanup.

All prior EGL error accesses are mechanically redirected through Errors(). Existing Pthreads import and native-worker std::exception fences now include Bindings/Current lookup and active-state setup, so the new checked key/publication failures cannot unwind across lifted nounwind calls or the native worker entry. Successful active-state restoration and all lifecycle hook order remain unchanged. Existing EGL import and game helper fences already cover their new accessor's standard exceptions. Direct host API failures remain exceptions; resource failure branches are source-reviewed, not fault-injected.
