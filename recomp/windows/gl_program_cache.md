# Native program configuration and binary cache

`GlHost` exposes core `glProgramParameteri`, `glGetProgramBinary`, and `glProgramBinary` through the same owned current ANGLE context. The commands are appended after the 147 existing marker identities. The existing `glGetProgramiv` bridge also admits the one-integer `GL_PROGRAM_BINARY_RETRIEVABLE_HINT` query.

Program binaries are opaque bytes produced and consumed by the pinned native driver. The adapter does not invent binary formats, compiled programs, link results, or portable cache compatibility. Failed/corrupt imports retain the driver's actual status and errors. Original Unity has both cache-read and cache-write paths, but the observed failure only establishes its program-parameter call; live cache contents and branch execution were not logged.

Positive binary input is copied through the tracked guest-memory read protocol. A zero input length reaches native ANGLE with a null byte span. Negative input lengths fail closed with an explicit checked-transfer-scope diagnostic: the pinned ANGLE implementation does not validate them before converting to an unsigned stream length. This adapter does not manufacture a GL error or link result for that unsupported span. Copied transfers are bounded to 64 MiB.

Binary output preserves native write order: format, written binary prefix, then optional length. Pinned ANGLE writes format and a zero length even when insufficient capacity raises `GL_INVALID_OPERATION`; those genuine scalar writes are published. Invalid-program and unlinked-program validation leaves outputs untouched. Native null-output behavior is retained, and output bytes beyond the actual prefix are untouched. Guest writes participate in the existing memory invalidation protocol, including scalar writes that leave the same value.
