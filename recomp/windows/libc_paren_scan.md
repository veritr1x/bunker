The original frame-pacing recovery run reached `sscanf` at LR `0x701b61c0` with exact format bytes `(%u)\0`. Original FDE `0x701b6074..0x701b6264` passes one unsigned32 output at SP+12. It contains one `sscanf` call and no `vsscanf` call. Runtime input contents were not logged; no payload or parsed value is inferred. Boundary analysis is retained under `work/frame-pacing1-unsigned-scan-boundary1`.

Only the exact additional format `(%u)` is admitted. The existing HTTP/RTSP formats and prior four string/`%llu` profiles retain their behavior and import markers. The literal opening parenthesis does not skip leading input whitespace. The numeric conversion skips the six C-locale ASCII whitespace bytes, accepts an optional sign, and uses the existing 512-byte token bound including the sign. An assigned unsigned32 remains assigned when the closing literal is missing or mismatched. The checked four-byte output publication uses the shared guest-memory protocol.

Android13 [vfscanf.cpp](https://android.googlesource.com/platform/bionic/+/android-13.0.0_r1/libc/stdio/vfscanf.cpp) uses an unsigned integer conversion for this profile. The target [strtol.cpp](https://android.googlesource.com/platform/bionic/+/android-13.0.0_r1/libc/bionic/strtol.cpp) unsigned path saturates at UINT64_MAX and sets ERANGE34 on magnitude overflow; otherwise a negative sign applies unsigned negation. The scanner publishes low32 bits. Out-of-unsigned32 range and token-limit results are target implementation observations, not universal ISO C overflow guarantees. This does not introduce a general scanf grammar or foreign va_list adapter.
