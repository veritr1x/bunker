# Owned-thread priority component fixture

The same strict Android NDK C/assembly object supplies direct, volatile function-pointer and raw upper-register-poison getpriority callers to static Bionic ARM64 and the lifted Windows component. Native Android queries are checked against raw kernel priority normalization. Its only CFS mutation lowers a disposable native child, which then exits. This does not qualify Windows as Android CFS.

The Windows fixture uses actual Pthreads-created translated workers, actual native IDs, and owned DuplicateHandle leases. Each explicit UnityNormalClass level is independently checked through GetThreadPriority; only disposable owned worker levels change and the original value is restored before release/join. Getter success preserves guest errno; JNI equal setter preserves it and real changed setter clears it. Actual native errno, LastError and fenv preservation is checked. Direct/V/A static JNI calls preserve jvalue padding and canaries; diagnostic observers deliberately perturb native environment without supplying priority results.

The initialized bootstrap Process method remains native and static. Tests preserve the generic nonnative binding guard, reject platform binding conflicts and verify mixed RegisterNatives/UnregisterNatives transactionality. Platform bodies are not fabricated translated NativeEntry registrations. Passive expired owners fail decisively. Retained handles remain attached to the real terminated native object; known retired/negative IDs return ESRCH, while unknown targets and unsupported profile levels fail explicitly.

Existing Pthreads and worker-signal lifecycle tests run once on Windows, and existing JNI registration/reference tests once on Windows and Linux, using immutable copied support sources plus the same exact eight core overlays. No Linux Pthreads port, game startup, general scheduling fairness, CFS permissions/inheritance, forced TID reuse or injected OS failures are claimed. Core/error-sink/Install configuration occurs before workers; Pthreads outlives all service operations, and the adapter is drained before its attached live Host is destroyed.

Controller requires explicit --preparation, --out, --ndk and --toolchain. Each output directory is newly created; prior failures remain untouched. Source/tool/archive/primary pins are checked after execution. No game/cohort/authority or OS settings are modified.
