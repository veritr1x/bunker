# Bounded native descriptor duplication

Game13 naturally entered the public IL2CPP initialization body: two original %llu scans returned the actual buildDate638477124699603280, then original setlocale(6,empty) returned C.UTF-8 at8254d0b4. Its next real boundary was dup(fd1026), LR82553f20. The caller2553e6c loads that descriptor from an existing native file object. Mapper25bb4d8 retains a duplicate object for2554020 mmap; the metadata path257f664 maps then closes its original file object. Other callers share the mapper, and the old log has no parent/path snapshot, so this does not assert the exact natural pathname of fd1026.

The pinned original/primary proposal is work/game13-dup-audit/PROPOSAL.md (SHA8305b1c3d1e68f5ac90cd4f0496787c55a01e6ff60194c879bc95fab9f414ac8), evidence d25c16a2e9fca89143884b3e844a02144017b6b319237e8240037bba59d0a995. [Android13 dup.cpp](https://android.googlesource.com/platform/bionic/+/android-13.0.0_r1/libc/bionic/dup.cpp), its syscall manifest, Android13-5.15 fs/file.c and [POSIX dup](https://pubs.opengroup.org/onlinepubs/9699919799/functions/dup.html) establish a new per-fd lifetime referencing the same open file description, with the new FD_CLOEXEC clear. Windows [native _dup](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/dup-dup2) and [DuplicateHandle](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-duplicatehandle) provide actual duplication, not a pathname reopen.

`FileSystem::Dup(int32_t)` appends its int32 import after rename and uses the existing production exception fence. Each Descriptor independently owns one native CRT fd and its own logical close_on_exec bit. The shared OpenDescription owns the I/O mutex, existing access/status policy and mount writable/device metadata. Open sets logical CLOEXEC from Android O_CLOEXEC; Dup clears it only on the new descriptor. Host Windows handles remain non-inheritable by checked SetHandleInformation, independently of that guest bit. No fcntl/exec/fork behavior is fabricated or claimed.

Read/Write/Seek/FStat/file-Mmap operations share the same I/O lock across aliases; append/binary/sync handling is retained. Close removes/closes only its per-fd owner. Dup pins its source, obtains I/O outside the registry mutex, then locks/revalidates the exact table object/native state before `_dup` and publication. This follows the established file-Mmap io->Impl lock order. Close/reuse can win and yieldEBADF; a stale descriptor cannot call CRT invalid-parameter handlers or silently acquire another native object. RAII closes unpublished native copies on validation/allocation/publication failure; source and published aliases remain owned. Success preserves guest errno. Dup changes no mapped page, owner generation, lease count or epoch.

The supported guest namespace remains1000..INT32_MAX. Dup chooses its lowest unused slot; Open keeps its prior monotonic cursor but skips occupied slots and checks the range, so a Dup cannot be overwritten by later Open. This is an explicit bounded virtual-fd profile, not full POSIX minimum0 or standard-descriptor support. FILE/DIR tokens retain separate domains. Shared flags are the existing immutable I/O policy with CLOEXEC removed; this does not introduce a general F_GETFL/F_SETFL surface.
