# Bounded Android 13 setlocale

This adapter implements the complete two-state behavior in pinned Android13 [locale.cpp](https://android.googlesource.com/platform/bionic/+/android-13.0.0_r1/libc/bionic/locale.cpp), [locale.h](https://android.googlesource.com/platform/bionic/+/android-13.0.0_r1/libc/include/locale.h) and [primary locale tests](https://android.googlesource.com/platform/bionic/+/android-13.0.0_r1/tests/locale_test.cpp). Fresh source hashes match the three previously accepted locale-audit files. It extends the earlier newlocale/uselocale/freelocale adapter; the old locale.md unresolved-setlocale sentence describes that older checkpoint.

Original IL2CPP API entry8254d094 is statically predicted to call setlocale(LC_ALL=6,empty string) at8254d0b0, before entering inner825724b8. This component was developed independently while game12 was prepared. Game12's actual frame stopped at unavailable Windows audio before resume/render, so it establishes no natural scanf/setlocale/IL2CPP-init entry. No manual init call is used here.

`LibC::SetLocale(int32_t,const char*)` accepts signed Android category0..12. Invalid category returnsNULL/EINVAL22 before reading a name, including an unreadable nonnull name. NULL queries the current global profile. The five exact names are C/POSIX (canonical C) and empty/C.UTF-8/en_US.UTF-8 (canonical C.UTF-8). Other names returnNULL/ENOENT2 without changing mode. All successes/queries preserve guest errno. Every valid category shares the same global bit, as Bionic does; there is no fabricated per-category table or LC_ALL composite name.

Each LibC instance represents one virtual guest process, initiallyC.UTF-8; both original modules in the game share that provider. Global set/query and global MB_CUR_MAX reads use its existing mutex. The old unconditional global maximum4 now reads that bit (UTF8=4,C=1). Explicit owned locale objects retain their own maxima and per-thread UseLocale selections are unchanged. In particular newlocale(empty) still creates a fresh explicitUTF8 object even while globalC. Provider identities still isolate independent guest runtimes and stale thread identities.

The result is one of two immutable canonical string literals with process lifetime. It is not a borrowed input/std::string pointer, a heap allocation to free, or mutable guest storage. Query and global state updates do not rewrite or retire any guest locale-object metadata. The import is appended after sscanf, preserving all prior marker identities including free, and uses the existing typed bridge/exception fence. No host CRT locale/environment is delegated to or changed; the Bionic empty alias ignores even the provider's explicit virtual LANG/LC_* values.

Bionic's original global bool is unsynchronized. This adapter serializes its own operations to avoid host data races while retaining source-defined sequential behavior. These tests do not claim POSIX setlocale is universally thread-safe or reproduce undefined concurrent timing. They also do not provide arbitrary cultures, wide-character conversions, localeconv, duplocale or new `_l` APIs.
