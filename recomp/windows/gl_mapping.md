# Core GLES mapped buffers

The original null call at LR `0x7046fdfc` is the `glMapBufferRange` slot at context offset `0x5e0`. The original loader resolved both the core name and its optional EXT fallback to zero. The preserved terminal arguments are target `0x8f37` (COPY_WRITE_BUFFER), offset zero, length `0x60`, access `0x36` (WRITE, INVALIDATE_RANGE, FLUSH_EXPLICIT, UNSYNCHRONIZED). This establishes the called API and arguments; it does not establish a rendered frame. Boundary evidence is `work/leaf-rounding1-null-call-boundary1/acceptance.json`, SHA256 `bf7adc7519412b88f3d392a9088e5a1b4f3685ffbb31dddafce0bfd023470b03`.

Three commands append after the existing marker catalog: `glMapBufferRange`, `glUnmapBuffer`, and `glFlushMappedBufferRange`. Offset and length use signed Android LP64 64-bit arguments; map returns a 64-bit data address and unmap returns a one-byte GLboolean. The nullable EGL/dlsym service resolves installed typed guest markers. No native code address is exposed. Core lookup succeeds, so the original optional EXT fallback is unnecessary.

A successful map returns the actual ANGLE data address. There is no provider shadow buffer or substituted GL store. ANGLE validates target, range, access flags, already-mapped state and allocation, and determines all results and GL errors. Negative or excessive native ranges are not changed into successful mappings. Flush offsets remain relative to the mapping start. Invalidated/unwritten bytes and modified but unflushed explicit-flush bytes retain their native undefined-data rules; the adapter does not fill them with invented values. Buffer access and synchronization remain the caller's native GL obligations.

The registry stores only the actual address, length, buffer name and share-group identity. A group originates from a successful native `eglCreateContext` and its actual share argument. It survives deletion of one member while a shared or deferred-deleted current context remains. Identical integer names in nonsharing groups are separate records; shared contexts access the same record. A successful native unmap ends the tracked mapping even when the actual result is GL_FALSE due to data corruption. Successful `glBufferData` replacement or `glDeleteBuffers` retires the affected tracked ranges. Native API errors retain the existing record.

Native map completion is published with `InvalidateGuestMemory`. Flush and unmap acquire the shared guest-memory ordering fence, then release it before calling the real driver. They never hold the global guest-memory lock across GPU synchronization. After a native storage retirement and before returning the API, range invalidation clears stale exclusive reservations without dereferencing the old address. The same invalidation covers provider teardown. EGL's retirement observer runs after potentially retiring operations, outside the EGL mutex, and conservatively invalidates mapped ranges before pruning dead groups. This preserves the existing GL-to-EGL lock order and never calls guest code. Deferred/current context identity follows the existing EGL model, including held contexts at termination. Provider destruction requires all active GL/EGL calls to have quiesced and EglHost to outlive GlHost.

The outer GL and EGL invoke scopes preserve native errno, LastError and floating-point environment around context/DPI selection, callbacks and driver calls. Existing command ordinals and all other command tables remain intact. Capability strings are not rewritten and unsupported signatures continue to return no typed procedure.

The Khronos core references specify real mapped pointers, automatic unmapping on deletion/data-store recreation, flush-relative offsets, error conditions and the access rules: [MapBufferRange and UnmapBuffer](https://raw.githubusercontent.com/KhronosGroup/OpenGL-Refpages/main/es3.0/glMapBufferRange.xml), [FlushMappedBufferRange](https://raw.githubusercontent.com/KhronosGroup/OpenGL-Refpages/main/es3.0/glFlushMappedBufferRange.xml).
