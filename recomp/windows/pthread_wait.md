# Optional condition-wait interruption transport

This gate addresses the actual Game18 finalizer wait at `825505d4` without enabling game signal delivery. `SetWaitHooks` is optional and immutable before the first Create or CondWait attempt. No hooks retains the existing condition-variable path. The callback-only API adds no SignalHost linkage requirement.

A configured wait acquires a live generation-based channel before releasing the mutex. Its per-waiter ticket is enrolled under the condition lock before the real logical mutex release. Only CondWake marks tickets; signal selects one unmarked ticket, broadcast selects all. A transport wake cannot advance the condition sequence, synthesize EINTR or complete the wait. Generation is sampled before checking the condition or mutex, closing notification-before-sleep races. Relative waits are bounded to one second, including indefinite waits, so a failed notifier cannot permanently strand an already signaled ticket.

The original absolute deadline and clock remain fixed, with another deadline check after checkpoint time. ConditionReleased and MutexReacquire checkpoints run on the waiter, outside provider locks while that worker does not own the guest mutex. Another worker may own it. The exact mutex control remains pinned and counted as busy through reacquisition. A callback exception withdraws enrollment and reacquires that mutex without more callbacks before propagating. Notifications attempt all committed recipients outside locks and propagate the first exception. Callback channels must honor the relative bound, preserve native errno/fenv, return normally and have passive destruction; dispatch implementations must preserve native environment separately from guest context changes.

The fixture uses the same Android NDK object for lifted Windows execution and a native ARM64/QEMU reference linked to ARM64 glibc. Opaque test buffers accommodate both native mutex layouts; this is a condition-wait behavior comparison, not a claim of Bionic/Linux internal layout identity. The reference sends actual SIGUSR1 while waiting and verifies no early completion, normal notification, timeout and mutex ownership. Windows additionally checks same-worker actual State/arguments, real SignalHost pending deferral and later dispatch, no false condition completion, contended reacquisition, all callback failure phases, notifier failure, one-vs-all notifications, and errno/fenv preservation. The Linux native C++ test qualifies only the portable generation channel; `pthread_host.cpp` is Windows-only. Existing Windows pthread and worker-lifecycle tests qualify the unconfigured route once each.

The component callback is a labelled test signal-model boundary, not an original collector handler. No GC records, collector acknowledgements, stop-world operation, physical root publication or production game delivery are synthesized or qualified. Future composition must admit only separately qualified provider phases before consuming a signal. In particular a list of State pointers does not publish parent/native-only roots. The adapter and its channels must outlive worker drain.

All candidates are immutable, archive the support commit and only the nine owned overlays, pin the toolpair, preserve output, and rehash executed source/binary/log inputs before acceptance. Game18 observations are in `work/game18-condwait-plan/REPORT.md`; Android no-EINTR evidence is pinned there.
