# Object-label query bridges

The original `draw-buffers1` run reached a null call with LR `0x70498f04`. The wrapper selects either core `glGetObjectLabel` or `glGetObjectLabelEXT`; its runtime branch was not logged. The observed arguments were identifier `0x1702` (`GL_TEXTURE`), object name 61, capacity 128, null length pointer and a 64-bit output pointer. Both lookups returned zero. [The causal boundary](../work/draw-buffers1-label-query-boundary1/acceptance.json) is pinned by `76b3b381f451d6da468e3475fa0c0c300b75a83cab4c15368f820367a688788e`. The component uses real TEST-owned textures and labels, without claiming their names or data were the original runtime values.

Both bridges have signature `void(GLenum, GLuint, GLsizei, addr_t, addr_t)`: three 32-bit scalars, signed capacity and two full 64-bit output pointers. They append indices 143 and 144, preserving the existing 143-command prefix for 145 commands total. Native ANGLE supplies the labels and validation. The two production pins are `gl_host.cpp` = `53f5d4f18a1aa1f030f9e487b3e9811b0f05ae5a07ac0bc3dd773c74398e1a38` and `gl_label_impl.inc` = `63f3fbcfdcd6f6e0af4f306d77a4e9ee3d2f1670b56e11850e95aacda8c2aef6`. [The source manifest](../work/label-query-source-preparation1/production-sources1.json) has SHA-256 `9056c72e0df6f59db3655c42b9223254a929d90c6315f71a87a77e0911217403`; [root's complete-source inverse review](../work/label-query-root-source1/acceptance.json) is `a9eeec342c992cf649d41a17b066bc236ea05bdebe801956b49ace304d7bad50`.

Each call uses a private native length even when the guest length pointer is null. A null label pointer or zero capacity follows the pinned driver's full-label-length query behavior. Positive nonnull label output is staged in owned storage, bounded at 64 MiB. On success, only the returned character prefix and terminating NUL are published, followed by the optional four-byte length. This preserves native overlap order and untouched output suffixes. Negative capacity delegates native validation before guest output access. Native errors publish neither label nor length; the existing per-context error queue preserves prior flags, including an identical preexisting error.

[Qualification Q1](../work/gl-label-query-qualification1/acceptance.json), SHA-256 `9a97419e7f6895c7eddd8528911f5e1f9925cd6cfba41c486d7d2bdb72e43782`, passed 1,021 checks: 87 actual NDK calls, 86 installed getter callbacks, 86 complete native-output comparisons and six publication checks. Both APIs run through direct calls, volatile function pointers and `eglGetProcAddress`. Existing typed core/EXT setters supply the native labels. Coverage includes the observed capacity-128/null-length shape, high-64-bit outputs, empty and embedded-NUL labels, full/truncated results, zero capacity, null label output, invalid identifiers/names/counts, pending errors and overlapping outputs. Full guarded buffers match native ANGLE without normalization. Same-value length/label writes invalidate guest exclusive reservations; failed queries preserve them. State1200/Memory64 and native errno/LastError/FENV checks also pass.

Reproduce with `test_gl_label_query.py --production-pins <frozen production-sources1.json> --out <fresh directory>` in the repository's WSL Python environment. The controller freezes source, NDK, retained lifter and native ANGLE inputs, compiles actual callers and the Windows component, executes the real driver and seals the receipt. This does not rerun the earlier DrawBuffers or mapping campaigns, advertise another query family, or establish an original-game frame.
