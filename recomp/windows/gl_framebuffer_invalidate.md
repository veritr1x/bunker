# Framebuffer invalidation hints

The original `label-query1` run reached a null function call with LR `0x70499978`. Context slot `+0x228` is loaded from core `glInvalidateFramebuffer`, with `glDiscardFramebufferEXT` as a guarded fallback into the same slot. The selected API cannot be distinguished from the failed call alone. Logged arguments were target `0x8d40` (`GL_FRAMEBUFFER`), count 3 and the exact array `0x8ce0, 0x8d00, 0x8d20` (color attachment 0, depth and stencil). [The causal boundary](../work/label-query1-fbo-boundary1/acceptance.json), SHA-256 `a615014c8248908656ea061f89338def03a1d99038458a6ef28b3a6d643e4f37`, also bounds the downstream audit: no additional clear or sub-invalidation API is established by this frontier.

Both typed bridges use `void(GLenum, GLsizei, addr_t)`: 32-bit target, signed 32-bit count and full 64-bit input pointer. They append two commands after the exact existing 145-marker prefix, for 147 total. Each invokes its real native ANGLE function. Supported positive, valid-target, nonnull arrays are snapshotted as `count * sizeof(GLenum)` into aligned owned storage, bounded at 64 MiB. Negative/zero counts and invalid targets reach native validation without reading the guest array. There is no invented attachment-count maximum; positive null arrays remain outside the valid copied-input contract. No host no-op, synthesized GL errors or capability change is introduced.

Coverage includes the logged target/count/list in high-64-bit read-only storage ending at a guard page, complete input canaries, zero/negative counts, invalid targets/selectors, pending error flags, signed scalar widths, native errno/LastError/FENV and State1200/Memory64 ABI preservation.

Invalidated attachment contents are undefined, whether or not the driver physically retains them. The fixture never compares those contents. Its real two-color-plus-depth/stencil FBO checks only the uninvalidated color attachment 1 and color attachment 0 after an explicit fresh clear; it makes no observation about invalidated depth/stencil values. These are native component checks, not an original-game frame or a claim about the driver's discard implementation.

Reproduce with `test_gl_framebuffer_invalidate.py --production-pins <frozen production-sources1.json> --out <fresh directory>` in the repository's WSL Python environment.
