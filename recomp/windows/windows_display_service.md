# Native Windows display adapter

Construct `WindowsDisplayService` after `AndroidContext`. It implements only the original constructor's reached calls: Context.getSystemService("display"), DisplayManager.getDisplay(int), Display.getDisplayId/getRotation/getWidth/getHeight/getRefreshRate/isWideColorGamut/getAppVsyncOffsetNanos/getPresentationDeadlineNanos, DisplayMetrics(), and Display.getRealMetrics with widthPixels/heightPixels/densityDpi. Other nonnull service names return null with a Java UnsupportedOperationException; pending String/argument exceptions are preserved, and null service name returns null as in Android13. An unsupported service query does not become a new native abort. The previously qualified DISPLAY_SERVICE constant is unchanged.

The adapter queries active Windows desktop topology through [EnumDisplayMonitors](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumdisplaymonitors), GetMonitorInfoW and QueryDisplayConfig. ID0 means the current primary Windows logical display. Other device names receive positive IDs retained for the adapter lifetime. Missing/removed IDs return null. Existing Display objects retain their last known data if the native output disappears, matching Android's cached Display-info behavior. This maps Windows logical outputs, not Android physical display identifiers. Ambiguous cloned-source timing is an explicit unsupported profile.

Pixel dimensions, quarter-turn rotation and the rational refresh rate come from the current Windows source mode and active path. Shcore supplies the actual scale percentage and effective-DPI query. The port maps Windows UI scaling to Android's 160 baseline (`round(scalePercent * 160 / 100)`); it logs the native effective DPI separately because that API may return process-virtualized 96 DPI. No process/thread DPI-awareness setting or display configuration is changed. Native queries save/restore errno, LastError and the full floating environment; conversion runs with masked FP exceptions and round-to-nearest.

The two timing values describe the approved **native-port scheduling policy**: app offset is zero because this one-frame host has no Choreographer phase advance; nominal presentation budget is the ceiling of the actual observed refresh period in nanoseconds. These are not Android compositor or DWM timestamp measurements. `isWideColorGamut()` reports false because this port's current window renderer exposes SDR/sRGB only; it does not infer the physical monitor's gamut. No refresh rate or monitor data is guessed. The [Android Display contract](https://developer.android.com/reference/android/view/Display) and [DisplayManager contract](https://developer.android.com/reference/android/hardware/display/DisplayManager) remain the Java-facing API shape.

Callbacks use weak adapter ownership and the existing unlocked JNI owned-frame protocol. The manager and Display payloads have real typed class ownership; getters return fresh locals. Native enumeration cannot unwind through its Windows callback. The JNI Long return transport is separately owned and qualified; no JNI core changes are made by this adapter.

Android13's [DisplayMetrics source](https://android.googlesource.com/platform/frameworks/base/+/android-13.0.0_r1/core/java/android/util/DisplayMetrics.java) has an empty constructor (line323), and these three primitive fields have no initializers. The factory therefore sets all three to zero without any native display query; a connected display is not required to construct it. Native population occurs only in getRealMetrics.
