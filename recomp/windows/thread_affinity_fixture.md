# Owned-worker affinity component

The same actual NDK C/assembly caller objects run with static Bionic on ARM64/QEMU and with the translated Windows component. Syscall122 carries raw64 number/size registers and signed pid low32, a full pointer, three ignored poisoned tails, and signed long64 result. The actual raw seven registers are observed before the Windows typed bridge narrows them. Output records/canaries and input mask immutability are checked.

QEMU8.2.2 has a pinned syscall-emulation divergence: ARM64 sched_setaffinity rejects non-word-multiple lengths, including4, before copy/target lookup. The actual NDK/Bionic len4 calls therefore explicitly record22 EINVAL divergences; they are never used as the Windows behavior oracle. Separate ordinary8B calls qualify NDK/QEMU syscall transport, actual native effect/readback/restoration, without implying Windows8B support. This is not full Windows/ARM64 affinity behavior parity.

An independent actual native Linux4B kernel oracle compiles the same request C source for x86_64 plus an explicit Android122-to-HOST-SYS_sched_setaffinity adapter and raw native assembly. It never blindly forwards Android122 as an x64 number. Its real allowed mask is queried first, and an actually allowed CPU below32 is selected; no guessed CPU0. Changes affect only a disposable child. It narrows, expands, checks unavailable-bit clipping and four-byte unaligned/guard/error ordering, and restores its exact original full mask before exit. Parent affinity is read-only and unchanged. Only native Linux4B canonical results/errno compare to Windows4B; CPU numbering and masks are independently checked against each actual host, not normalized into invented equality. Zero-length/null outside the Windows profile is measured separately.

Windows changes affect only an actual Pthreads-created translated worker with a retained duplicated native handle. Real process/system/group masks are independently queried. Tests narrow then expand within the actual process ceiling (not the previous thread mask), clip unavailable bits, verify native GetThreadGroupAffinity readback, and restore the original native mask before releasing/joining the worker. The released guest executes direct/indirect self-targeting calls with that restored mask. Known retired leases still refer to the same terminated object; valid masks yield ESRCH while inaccessible masks still yield EFAULT before target lookup. Read-only and exact4B-at-guard inputs expose writes or overreads. Caller/process affinity never changes.

Observer flags and actual native errno/LastError/fenv preservation, full translated State preservation, real fault/error ordering and three import exception fences are checked. Unsupported lengths/numbers/unowned targets are explicit profile boundaries, not fabricated kernel errors. Windows raw native status capture is used for fatal subprocesses.

The two new core files are frozen over exact bc438ce; Runtime, Pthreads lease, SignalHost, Sleep, Futex and LibC protected source hashes remain exact to the archive. Those previously qualified suites are not rerun. No process/default CPU-set mutation, foreign thread operation, TID-reuse fabrication, signal/root safety widening or game execution is performed. Setup/error sink and all native callbacks obey the core's lifetime/lock/environment contracts; no game mask value or worker role is inferred.
